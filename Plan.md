## 2️⃣ Создание базовой модели данных

- [ ] **Таблица `users`**  
  _Хранение данных пользователей: email, имя, хэш пароля._

- [ ] **Таблица `problems`**  
  _Хранение проблем пользователя с полем `status` и временем решения._

- [ ] **Таблица `messages`**  
  _Все сообщения диалога пользователя и AI, включая уточнения и feedback._

- [ ] **Таблица `solutions`**  
  _Отдельные решения для каждой проблемы, возможность отмечать успешное._

- [ ] **Настроить ORM** (Prisma / TypeORM)  
  _Удобная работа с базой данных и миграциями._

- [ ] **Реализовать миграции для таблиц**  
  _Гарантия корректной структуры БД на разных окружениях._

---

## 3️⃣ Реализация базового API

- [ ] `POST /problems` — создание новой проблемы  
  _Принимает текст проблемы, создаёт запись в БД, статус по умолчанию `unsolved`._

- [ ] `GET /problems/:userId` — получение истории проблем пользователя  
  _Возвращает список всех проблем с их статусами и датой решения._

- [ ] `POST /problems/:id/solution` — добавление решения AI  
  _Сохраняет решение, связывает с проблемой и сообщением._

- [ ] `POST /solutions/:id/feedback` — отметка решения как успешного/неуспешного  
  _Обновляет `isSuccessful`, при успешном решении меняет статус проблемы на `solved`._

## 6️⃣ Логика итеративного решения

- [ ] Если решение **не помогло** → генерировать новое решение  
- [ ] Если решение **помогло** → пометить проблему как `solved`  
- [ ] Сохранять **успешные решения** в истории пользователя  
- [ ] Проверить корректность цепочки сообщений и связи с решениями

## ⚡ Итог

MVP позволит пользователю:  
- Создавать проблему  
- Получать решения через AI  
- Итеративно пробовать решения  
- Сохранять успешные решения в истории  
- Смотреть свои прошлые проблемы и их статус  

> После MVP можно расширять функционал: embeddings, метрики, теги, рекомендации.
