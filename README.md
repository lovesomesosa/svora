# 🧠 Svora Manager

## 📌 Общая идея

**Svora Manager** — масштабируемое веб-приложение для студии звукозаписи, которое позволяет клиентам **бронировать студию**, управлять своими **музыкальными проектами (синглы и альбомы)** и взаимодействовать со студией в процессе работы.

Особенности:  
- Онлайн-бронирование студии  
- Личный кабинет с проектами (синглы / альбомы)  
- Управление треками внутри проектов  
- Разделение ролей (client / owner)  
- Архитектура с заделом на масштабирование  

---

## 🎯 Цель проекта

- Создать **реальный продукт для студии звукозаписи**

- Возможность дальнейшего превращения в SaaS

## 🔄 Основной процесс работы

### 1. Регистрация
- Пользователь создаёт аккаунт  
- Роль по умолчанию: `client`  
- Владельцы студии: `owner`  

---

### 2. Бронирование студии
- Пользователь открывает календарь  
- Видит:
  - свободные слоты  
  - занятые слоты (без деталей)  
- Выбирает:
  - дату  
  - время  
  - тип услуги  
- Создаётся `Booking`  

---

### 3. Работа владельцев
Владельцы:
- видят полный календарь  
- видят:
  - кто записан  
  - время  
  - услугу  
- подтверждают / отменяют брони  
- могут назначать ответственного  

---

### 4. Работа с проектами

Проект — это основная сущность:

- 🎵 **Single** (1 трек)  
- 💿 **Album** (несколько треков)  

---

### 5. Работа с треками
- Треки принадлежат проекту  
- В альбоме → несколько треков  
- В сингле → один трек  

---

### 6. Работа с версиями
- У каждого трека есть версии:
  - v1, v2, final  
- Файлы хранятся в облаке  

---

### 7. Комментарии
- Пользователь оставляет комментарии  
- Возможен таймкод  
- Взаимодействие с владельцами  

---

### 8. Завершение
- Проект получает статус `done`  
- Все данные сохраняются  

---

## 🧱 Структура данных

### 1. User
```ts
User {
  id
  name
  email
  passwordHash
  role // 'client' | 'owner'
}
```
### 2. Booking
```ts
Booking {
  id
  userId
  assignedTo // ownerId (nullable)

  date
  startTime
  endTime

  serviceType // 'recording' | 'mixing' | 'mastering'
  status // 'pending' | 'confirmed' | 'cancelled'

  createdAt
}
```
### 3. Project
```ts
Project {
  id
  userId

  title
  type // 'single' | 'album'

  status // 'recording' | 'mixing' | 'mastering' | 'done'

  createdAt
}
```
### 4. Track
```ts
Track {
  id
  projectId

  title
  order // порядок в альбоме (nullable для сингла)

  createdAt
}
```

### 5. TrackVersion
```ts
TrackVersion {
  id
  trackId

  versionName // v1, v2, final
  fileUrl

  createdAt
}
```
### 6. Comment
```ts
Comment {
  id
  trackId
  userId

  text
  timestamp // optional (00:45)

  createdAt
}
```

## 🔗 Связь данных

### Основные связи

- User → Bookings  
- User → Projects  
- Project → Tracks  
- Track → Versions  
- Track → Comments  
- Booking → может быть назначен owner

##🧠 Архитектурные решения
### 1. Project как ядро системы
- Один тип сущности для single и album
- Лёгкое расширение
- 
### 2. Гибкие роли (RBAC)
- client
- owner
- *(в будущем: engineer, admin)

### 3. Масштабируемый booking

#### Сразу закладывается:

- несколько комнат
- несколько владельцев
- разные услуги
  
### 4. Отделение файлов
- файлы НЕ в БД
- только ссылки (S3 / storage)

## ⚙️ Технологический стек
- Frontend: Next.js
- Backend: Next.js + Express.js
- База данных: PostgreSQL (опционально с pgvector для embeddings)
- Документация API: Swagger
- Файлы: S3
- Auth: JWT
- Version control: Git + GitHub
- CI/CD: GitHub Actions (тесты, линтинг, билд, деплой)
- Docker: контейнеризация backend + БД
